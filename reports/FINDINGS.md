# FINDINGS (журнал исследований)

Правила: только проверенные факты; у каждого — источник (файл/смещение/команда).
Предположения помечаются отдельно. Файл пополняется по ходу работы.

---

## 2026-10-31

### Контейнеры
- [ФАКТ] Внешний апдейтер: PE32 + оверлей; записи
  `u32 len; u32 size; UTF-16 name; u64 FILETIME`; PKCS#7 (Sony).
  Источник: `Update_DSCRX100M2V110.exe`, оверлей 0x68E800.
- [ФАКТ] UFU: `\x89UFU\r\n\x1a\n`, чанки `DATV/PROV/UDID/FDAT/DEND`,
  длины big-endian; DEND — CRC32 (BE) всего до него.
- [ФАКТ] FDAT: AES-128-ECB, ключ `E3B0C44298FC1C149AFBF4C8996FB924`,
  блок 1024 Б, `u16 crc16 + u16 size|0x8000`, добивка 0xFF.
- [ФАКТ] TPZL: `TPZL`, block_log=16 (64 КиБ), TOC в (offset,size),
  LZ77 потоки 0xF0/0x0F.
- [ФАКТ] В эталонных TPZL literal-куски всегда 4096 Б; max запись 65600 Б.
  Источник: `nflasha8`/`nflasha3`, `verify_tpzl.py`.
- [ФАКТ] WBI1 (`nflasha5`): заголовок `WBI1`, 0xA0, 9, 0x800498E0,
  0x20060224, 0x200, 0x0184DA00, 0x0F0F0F0F, 0x042EB000; данные с ~0x100000,
  энтропия ≈6.9. Семантика — [ОТКРЫТО]. Источник: `docs/04-wbi.md`.
- [ФАКТ] UXC: запись строки = `u16 id; u16 0x1E04; строка (ASCII/UTF-8); NUL;
  выравнивание 4`. Проверено на en/ru файлах. Таблица u16 в заголовке —
  [ОТКРЫТО].
- [ФАКТ] UXC-цвета: записи 8 Б `{u16 id; u16 type; u32 RGBA}`, type
  0x3A09 (color_cmn.uxc). Источник: `docs/03-uxc.md`.

### Разделы
- [ФАКТ] nflasha3 → FAT12 16 056 320 Б: `vmlinux.bin`, `initrd.img`,
  `av-cam.bin`, `bonobo.bin`, `sabin/`.
- [ФАКТ] nflasha8 → ext2 91 357 184 Б, 556 файлов.
- [ФАКТ] Карта разделов — из `partinf.conf` (см. docs/00-overview.md).

### Ядро и initrd
- [ФАКТ] Linux 2.6.29.6-rt24-alp_nl, gcc 4.3.3 (Sony CE Linux 6.0.0.4),
  сборка 19.12.2014.
- [ФАКТ] `initrd.img` — AXFS (Advanced XIP FS), сигнатура
  `48 A0 E4 CD` + "Advanced XIP FS".
- [ФАКТ] Ядро поддерживает cramfs/squashfs ramdisk (строки в vmlinux).
- [ФАКТ] AXFS разобран: суперблок и дескрипторы big-endian, таблицы
  хранятся byte-plane (value = p0 | p1<<8 | ...). Извлечено 562 файла
  и 74 симлинка; `/lib/sonyld.so` — ELF ARM динамический загрузчик (DYN, entry 0xE48).
  Источник: `docs/02-initrd.md`, `axfs_extract.py`.
- [ФАКТ] Уточнение: `node_index` для XIP задан в блоках по 4096 Б
  (смещение = значение × 4096); исправлено, после чего модули `*.ko`
  извлекаются как валидные ELF ARM EABI4.

### /usr (ext2)
- [ФАКТ] glibc 2.9 в `/glib`, интерпретатор бинарей `/lib/libsonyld.so`
  (в образе /usr отсутствует — вероятно, в initrd).
- [ФАКТ] `kmod`: ar6000.ko (WiFi Atheros), sdio_busdriver/sdio_lib/mmcioWrapper.
- [ФАКТ] `sabin`: 60 DSP-модулей, сигнатура `AA 0A 13 91`, имена
  `SA<NAME>__0.01` (например `SABFNR__0.01`, `BFNR____0.01`).
- [ФАКТ] `share/app`: 204 файла, UXC-ресурсы, шрифты, `global.xdb`, `lang.uxb`.
- [ФАКТ] `bin/up.sh` использует флаги `/setting/updater/mode*` для выбора
  режима следующей загрузки (UFP/обычный).

### DSP
- [ФАКТ] `av-cam.bin` (6 451 592 Б) — сырой ARM-код, `ORIL` по смещению 4,
  строки символов `Camera::HAPI::…`, `wbi_*`, `lzo`?
- [ФАКТ] В нём есть `Camera::HAPI::Start_Art_Effect`,
  `PRM_REQ_FILTER_ART_EFFECT`, `Miniature`, `Soft_Focus`, `Richtone`.
- [ФАКТ] Таблица параметров 0x5C4278..0x5C4804: 118 записей по 12 Б
  `{u32 size; u32 dsp_addr(0x010C0000+); u32 id}`, ID 0x1F0..0x340;
  art-параметры 0x2BC/0x2C8/0x32C → 0x010C012F/0x010C0132/0x010C0155.
  Прямых ссылок на адреса в коде нет.
- [ФАКТ] База загрузки `av-cam.bin` = 0xC3440000: адреса 0xC3920xxx —
  Thumb-указатели, Ghidra декомпилировала `FUN_c392061c`.
- [ФАКТ] Карта кода DSP: 23 088 функций, ~2,77 МБ кода; крупнейшая
  0xC3719824 (9288 Б). Карта — `ghidra_out/avcam_funcs.tsv`.
- [ФАКТ] В `av-cam.bin` есть таблица трассировки: `{u32 trace_addr; u32 0;
  char signature[]}`; адреса указывают внутрь функций (например,
  `0xC3920787` → `Start_Art_Effect`), не на их начало.
- [ФАКТ] `Start_Art_Effect` — обёртка `FUN_c392077c`: ставит асинхронный
  запрос с RAM-структурой `0xC3C7FED8` и callback `0xC391A5CD`; сам
  фильтр не считает.
- [ФАКТ] Цепочка `Start_Art_Effect` → `0xC3915CE0` (планировщик) →
  callback `0xC391A5CC`; callback вызывает `0xC391A93C`, `0xC3791D2E`,
  `0xC3791DD2`, `0xC384184E`, `0xC384196A`, `0xC3791EC2`, `0xC3792024`,
  `0xC3792140`, `0xC391A804`, `0xC3841A6A`.
- [ФАКТ] Обработчик эффекта читает параметры из RAM-структуры
  (`0xC3C7FED8`), а не из статических таблиц; в подфункциях
  `0xC3791D2E`/`0xC384184E`/`0xC3792024`/`0xC384196A` — типовые операции
  над изображением и флагами.
- [ВЫВОД] Числовые «рецепты» эффектов не статичны: формируются в рантайме
  из параметров хоста.

### Ошибки/уроки
- [ФАКТ] `wrapperArtFilter.so` не имеет потребителей; рабочая копия
  `setArtFilter` — в `libObj.so` (символ 1646 Б).
- [ФАКТ] Копии `setArtFilter` совпадают по прологу, размеру (1646 Б) и
  логике; различаются только кодировкой BL-вызовов (разные расстояния).
  Источник: `wrapperArtFilter.so` 0x1754, `libObj.so` 0x557810.
- [ФАКТ] Наш TPZL имел literal 65535 вместо 4096 → камера не загрузилась
  (причина отказа на стороне устройства не подтверждена логом).


## Раунд 2: новые факты

- `bonobo.bin`: count=9 524, записи по 16 Б (152 384 Б) + хвост 19 752 Б
  (9 876 `int16`) — суммы сходятся.
- `sabin`: контейнер, внутри с 0x100 (или 0x80) лежит boot-образ
  `3D 00 xx B0` + тег `B1`/`B2`/`B4`.
- `libsonyld.so`: без `DT_NEEDED`, entry `0xE48`; утилиты `/bin`
  используют его как `PT_INTERP`, приложения — glibc-загрузчик.
- UXC `string_english`: 3 694 записи, id `0xE000..0xF34D`; старшее u16
  поля `0x0C` совпадает с первым значением таблицы (308/478).
- `libObj.so`: Ghidra base `0x10000`; `openLayout` = `FUN_002f277c`,
  разбор UXC — в конвертере (`vtable+0xC/+0x10`).
- DSP: `0xC391A5CD` — продолжение внутри `FUN_c391a5a8`, не точка входа;
  принудительный `TMode=1` позволил декомпилировать.
- DSP-стадии — геометрия/выравнивание, без LUT и коэффициентов.
