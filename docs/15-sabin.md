# Модули `sabin` (DSP-алгоритмы)

60 файлов в `/usr/sabin`, имена `sa_*.bin` (например `sa_bfnr.bin`,
`sa_jpeg_enc_1core.bin`, `sa_camdsp_bayer.bin`, `spica_*_step1/2.bin`).

## Заголовок (по двум файлам)

| Смещение | Поле | `sa_bfnr` | `sa_jpeg_enc_1core` |
|---|---|---|---|
| 0x00 | magic | `AA 0A 13 91` | то же |
| 0x04 | u16/u16 | `0x0002`,`0x0100` | то же |
| 0x08 | u16/u16 | `0x000B`,`0x0100` | `0x01E1`,`0x0100` |
| 0x0C | u16/u16 | `0x0008`,`0x0001` | `0x0002`,`0x0001` |
| 0x10 | u32 | 0 | 0 |
| 0x14 | имя (16 Б) | `SABFNR__0.01` | `SAJPGE_CLF4_` |
| 0x24 | u32 | `0x05000008` | `0x05000002` |
| 0x28 | u32 | 1 | 1 |
| 0x2C | u32 | 1 | 1 |
| 0x30 | u32 | 0 | 0 |
| 0x34 | имя (16 Б) | `BFNR____0.01` | `JPGENC_CLF4_` |

Значения 0x08/0x0C, вероятно, связаны с размером кода/секций
(ПРЕДПОЛОЖЕНИЕ). Второе имя — короткое имя модуля.

## Инвентарь

`data/inventory/sabin.txt` — 60 записей: имя, размер, SHA-256.

## Встроенный образ (ФАКТ)

Начиная со смещения **0x100** (у малых модулей — 0x80) лежит вложенный
образ с заголовком того же типа, что у загрузчиков:

```
3D 00 xx B0 | "B1"/"B2"/"B4" | u16 | ...
```

| Модуль | Смещение | Тег |
|---|---|---|
| `sa_bfnr.bin` | 0x100 | `B1` |
| `sa_jpeg_enc_1core.bin` | 0x100 | `B1` |
| `sa_camdsp_bayer.bin` | 0x100 | `B4` |
| `sa_zima_startup_zma0.bin` | 0x80 | `B2` |

То есть `sabin` — контейнер (заголовок + имена), внутри которого лежит
boot-образ (`B1`/`B2`/`B4`) с полезной нагрузкой.

## Полезная нагрузка (наблюдения)

- Заголовок вложенного образа занимает `0x2E0` байт (поле по смещению
  `0x110`), дальше — полезная нагрузка (у `sa_bfnr` 23 204 Б).
- Энтропия заголовка ~4.8, нагрузки ~6.25.
- Сигнатур zlib (`78 9C`), gzip (`1F 8B`), xz и lzma нет;
  ARM-прологов `E92D` в начале нет.

То есть нагрузка — не «чистый» ARM-код и не стандартное сжатие;
вероятно, проприетарное кодирование/шифрование (ПРЕДПОЛОЖЕНИЕ).

## Ограничения

Формат кода внутри модулей (ARM? DSP?) не разбирался: сигнатура не ELF,
точка входа и карта памяти неизвестны.
