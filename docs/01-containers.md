# Контейнеры прошивки

## 1. Внешний контейнер апдейтера (ФАКТ)

PE32 + оверлей. Заголовок: magic `40 4C 43 CE`, затем поля, GUID,
таблица записей:

```
u32 name_len; u32 size; UTF-16LE name; u64 FILETIME (не у всех записей)
```

29 записей, данные подряд, в конце — PKCS#7 SignedData (Sony, DigiCert).
Служебные записи `!!!<GUID>` не имеют данных.

## 2. UFU / FDAT

```
89 55 46 55 0D 0A 1A 0A        сигнатура
[u32 BE len]["DATV"] u32=1     версия контейнера
[u32 BE len]["PROV"] u32=1
[u32 BE len]["UDID"] ...       USB ID: VID 0x054C, PID 0x047D/0x0448/0x0749/0x074A/0x03E2
[u32 BE len]["FDAT"] ...       зашифрованный образ
[u32 BE len]["DEND"] u32 BE    CRC32 всего, что до DEND
```

FDAT: AES-128-ECB, ключ `E3B0C44298FC1C149AFBF4C8996FB924`.
Блок 1024 Б: `u16 CRC16 (сумма 16-битных слов data[2:])`,
`u16 size|0x8000 (последний)`, данные ≤1020, добивка `0xFF`.
Расшифрованный заголовок: `UDTRFIRM`, CRC32, `0100`, модель, регион,
смещения firmware/fs.

## 3. TAR (образ прошивки)

49 записей: конфиги (`mount.conf`, `partinf.conf`), калибровки EQ,
`*.sum` (CRC32), образы разделов `0700_part_image/dev/nflasha3/5/8`,
UXC-образы интерфейса.

## 4. TPZL (LZPT) — образы разделов

```
"TPZL"; u32 block_log (=16 → 64 КиБ); u32 toc_offset (=0x18);
u32 toc_size; 8 байт нулей; TOC: (u32 offset, u32 compressed_size)*
```

Каждая запись распаковывается LZ77-потоками до 64 КиБ:

- `0xF0` — сжатый поток: байт флагов, литералы, ссылки
  (старший ниббл — индекс длины `[3..16,32,64]`, 12 бит — дистанция);
- `0x0F` — литеральный поток: `0x0F`, байт, `u16 len`, данные.

**Эталонные ограничения (важно):**
- literal-куски в оригинале — **всегда 4096 байт** (571 и 254 шт.);
- максимальный размер записи TOC — **65600 байт**.

Наш упаковщик писал куски по 65535 — вне эталона (см. отчёт).

## 5. WBI1

`nflasha5` начинается с `WBI1`, затем поля `0xA0`, `0x09`,
`0x800498E0`, `0x20060224`, `0x200`, `0x0184DA00`…
Семантика полей — **НЕИЗВЕСТНА** (не разобрана).

## 6. UXC

Ресурсный контейнер: `"uxc"`, байт версии `0x07`, далее таблица и
строковые записи `u16 id; u16 (0x1E04); ASCII/UTF-8 строка с NUL`,
выравнивание по 4. Точная семантика таблицы — **НЕИЗВЕСТНА**.
