# Линковка `.ko` и декомпиляция тел

## Инструмент

`tools/link_ko.py` собирает ET_REL-модуль в плоский образ:

- секции с `SHF_ALLOC` раскладываются с выравниванием от базы `0xBF000000`;
- применяются релокации `ABS32`, `REL32`, ARM-ветви (`PC24/CALL/JUMP24`),
  Thumb `BL`;
- неопределённые символы ищутся в `data/kallsyms.txt` (адреса ядра);
- рядом пишется `.syms` — карта `адрес / имя / тип`.

Для `unidrv1.ko`: 17 секций, 110 100 Б образа, **2 681** релокация.

## Результат

После линковки Ghidra декомпилирует тела с разрешёнными внешними
вызовами (например `func_0xc01ecd14` — функция ядра вместо нуля).

Проверено на `sdm_setup_partition`, `sdmlzp_request`,
`mms_sdmblk_do_ioctl`.

## Замечание

Сравнения заголовка раздела в `sdm_setup_partition` идут с данными по
`0xBF003C34`/`0xBF003C38`; там лежит ASCII `82461.00`/`1.00` — это
похоже на версию/идентификатор, а не на «магию» раздела. Требует
уточнения.
